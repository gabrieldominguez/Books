Referencia rápida del lenguaje de Windows PowerShell

 

Compatibilidad nativa con distintos sistemas de tipos

Windows PowerShell adapta los objetos WMI, XML, ASDI, ADO y COM para proporcionar una sintaxis común que permite obtener acceso a sus propiedades y métodos.  

Ejemplo
$g = Get-WmiObject Win32_Process

$g[0].Name  # en lugar de $g[0].Properties[“Name”]

Break (uso en scripts)

El comando break permite salir de un bucle. Puede usar una ETIQUETA opcional para interrumpir el bucle.

Ejemplo:

while (1)

{        $a = valor

          if ($a –eq 1) break;

}

Continue (uso en scripts)

La instrucción continue pasa a la siguiente iteración de un bucle sin salir de él. Ejemplo:

while (1)

{               $a = valor

                if ($a –eq 1) (continue)

            # No se llega a esta línea a menos que $a == 1

}

#  Nunca se llega a esta línea.

Agregar un punto al comienzo

Al agregar un punto al comienzo, se pueden ejecutar funciones, bloques de script y scripts en el ámbito actual en lugar de hacerlo en el ámbito local. Ejemplo:

. MiFunción

 

Si MiFunción define una variable, ésta se define en el ámbito actual y no en el ámbito local de la función.

$a = {$x = Get-Process | Select –First 2}

. $a    #Evalúa el bloque de script en el ámbito actual

Orden de ejecución

Windows PowerShell intenta resolver los comandos en el orden siguiente: alias, funciones, cmdlets, scripts, ejecutables y archivos normales.

 

For (uso en scripts)

[:etiqueta] for ([inicialización]; [condición]; [iterador]) {}

 

Ejemplo:

for ($i = 0; $i –lt 5; $i++) {Write-Object $i}

 

Foreach (uso en scripts)

[:etiqueta]

foreach (<identificador> in <colección>) {}

<Expresión> | foreach {}

<Expresión> | foreach {BEGIN{} PROCESS{} END{}}

 

Ejemplos:

$i = 1,2,3

foreach ($z in $i) {Write-Object $z}

Get-Process |foreach {BEGIN{$x=1}

       PROCESS{$X++}

       END{“Procesos de $X”}}

 

Funciones (uso en scripts)

function MiFunción {

                write-object $args[0]

}

 

function test ([string]$label=“etiqueta predeterminada”,[int]$start=0)

{ BEGIN {$x=$start} PROCESS {“$label: $_”’; $x++}

     END{“$x total”}

}

Ámbitos (uso en scripts)

Se pueden crear instancias de variables y otros elementos de datos en diferentes ámbitos:

·                Las variables del ámbito global pueden usarse en todos los ámbitos.

·                Las variables del ámbito de script pueden usarse en todos los ámbitos del archivo de script.

·                Las variables de ámbito local pueden usarse únicamente en el ámbito local y en sus ámbitos secundarios.

·                Las variables de ámbito privado sólo pueden usarse en dicho ámbito. 

Un ámbito se crea en el cuerpo de una función del shell (consulte la forma de crear funciones)

 

Ejemplo:

$global:a = 4

$script:a = 5

$local:a  = 3

$private:a = 6

Switch (uso en scripts)

La variable $_ está disponible en el script. $_ representa el valor que se está evaluando en ese momento. Si se utiliza una matriz en una instrucción switch, se comprueba cada elemento de la matriz.

Ejemplo:

$var = "palabra1","palabra2","palabra3"

switch -regex ($var) {

"palabra1"  {"Coincidencia múltiple exacta" + $_ }

"palabra2"  {"Coincidencia múltiple exacta" + $_ }

"w.*2"   {"Coincidencia de patrón exacta" + $_ }

default  {"Coincidencia múltiple predeterminada" + $_ }

}

 

Salida:

Coincidencia múltiple exacta palabra1

Coincidencia múltiple exacta palabra2

Coincidencia de patrón exacta palabra2

Coincidencia múltiple predeterminada palabra3

Análisis

Windows PowerShell cuenta con dos modos de análisis: comando y expresión. En el modo de expresión, Windows PowerShell realiza el análisis del mismo modo que la mayoría de lenguajes de alto nivel: los números son números, las cadenas deben escribirse entre comillas, etc. Las expresiones son cosas como las siguientes:

2+2

4

"Hola" + " mundo"

Hola mundo

$a = "hola"

$a.length * 13

26

Cuando el análisis se realiza en modo de comando, no es necesario escribir las cadenas entre comillas y todos los elementos se tratan como si fueran cadenas a excepción de las variables y los elementos entre paréntesis. Por ejemplo:

   copy users.txt accounts.txt     

users.txt y accounts.txt se tratan como cadenas

   write-host 2+2           

2+2 se trata como una cadena y no como una expresión que debe calcularse

   copy $src $dest          

$src y $dest son variables. A largo plazo puede resultar muy beneficioso no tener que utilizar las comillas al trabajar en un shell de comandos, ya que esto implica escribir menos.

El modo de análisis viene determinado por el primer símbolo que se encuentra. Si el token es un número, una variable o una cadena entrecomillada, el shell realiza el análisis en modo de expresión. Si la línea comienza con una letra, una Y comercial (&) o un punto (.) seguido de un espacio o una letra, el análisis se realiza en modo de comando.

2+2

El modo de expresión comienza con un número.

"texto"

El modo de expresión comienza con comillas.

texto

El modo de comando comienza con una letra.

& "texto"

El modo de comando comienza con una Y comercial.

. "archivo.ps1"

El modo de comando comienza con un punto seguido de un espacio.

.125

El modo de expresión comienza con un punto, seguido de un número (pero no un espacio o una letra).

.text

El modo de comando comienza con un punto, que forma parte del nombre del comando, ".text"

Resulta de gran utilidad poder combinar expresiones y comandos, lo que puede hacerse mediante paréntesis. Dentro de los paréntesis, el proceso de detección del modo de análisis comienza de nuevo.

Write-Host (2+2)

2+2 se trata como si fuera una expresión que tiene que evaluarse y se pasa al comando Write-Host.

(Get-Date).day + 2

Get-Date se trata como un comando, y el resultado de su ejecución pasa a ser el valor izquierdo de la expresión.

Los comandos y las expresiones se pueden anidar sin restricciones.

Write-Host ((Get-Date).day + 2)

Get-Date es un comando. ((Get-Date).day+2) es una expresión y Write-Host ((Get-Date).day + 2) es de nuevo un comando.

Write-Host ((Get-Date) - (Get-Date).date)

El comando Get-Date se utiliza dos veces para determinar cuánto tiempo ha pasado desde medianoche (condición).
